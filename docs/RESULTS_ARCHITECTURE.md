# 成績查詢資料與載入流程

網站由 Vite 建置為靜態頁面。公開成績查詢使用原生 JavaScript，會員頁才載入 React；查詢頁無須再載入前端框架。

## 查詢時載入哪些資料

| 操作 | 讀取的資料 |
| --- | --- |
| 開啟成績頁 | `swim-results-recent.json`（最近 24 筆）和篩選索引；更新資訊另外讀取，不阻塞列表 |
| 輸入至少兩字的姓名 | `swim-athletes.json` 選手索引與所需的選手成績分區，最多四個分區 |
| 只輸入一字、姓名範圍過廣、只選賽事或項目、瀏覽全部 | `swim-results-public.json` 完整公開資料，僅下載一次並快取在目前頁面 |

姓名符合多個選手時，會保留所有相符 ID，不會只選第一位。分區讀取失敗時改用完整資料；查詢來源切換時以最新一次請求為準，避免較慢的舊請求覆蓋新結果。

目前資料包含 10,653 筆公開成績。完整資料約 2.65 MB；最近 24 筆約 6.7 KB，選手索引約 25.7 KB。姓名查詢通常只需索引與相關分區。實際傳輸量會因瀏覽器壓縮、快取和查詢姓名而不同。

## 資料格式與維護

- `assets/js/result-data.js` 是成績 tuple 欄位、解碼、排序與 PB 分組鍵的共用定義。產生器、成績頁、選手頁都使用它；欄位變更時先修改這裡。
- `crawler/build-public-data.mjs` 從來源資料產生最近成績、完整公開資料、選手索引與 32 個分區。重新同步成績後，執行 `pnpm swim:public-data`。
- `data/swim-results.json` 和 `data/swim-honours.json` 是同步工作的來源快照，需要保留在專案中；Vite 發布時不會複製到 `dist`。
- `assets/images` 中的 PNG 原始圖保留於專案，未使用的大圖不進入發布檔。不要以清理發布檔為理由刪除原始素材。
- 修改查詢索引或資料格式後執行 `pnpm test` 和 `pnpm build`。`scripts/test-result-search.mjs` 會比對姓名分區查詢和完整公開資料的結果。
